# RootKey 威胁模型

> 状态:v2.0 / 2026-10-06,对应 App 0.23.1、浏览器扩展 0.4.1
> 配套文档:[SECURITY_MODEL.md](SECURITY_MODEL.md)(密码学规约)、[crypto-vectors.md](crypto-vectors.md)(可验证向量)

本文写给想在不读代码的前提下判断「我的威胁能不能被这套设计覆盖」的人。每一条都对照当前代码核实过;
做不到的地方写成「已知局限」而不是含糊带过。v1.x 版本里有几条说法与代码不符(生物识别失败清空、
扩展取用需二次确认、本机令牌按会话轮换等),本版已全部改正,见第 10 节。

## 1. 组件与信任边界

```
┌──────────────────────────── 用户设备(信任) ────────────────────────────┐
│                                                                          │
│  App 界面(Flutter) ── FFI ──> Rust 核心:加解密 / 保险库 / 同步 / 签名     │
│                                   │  解锁期间密钥只在内存,锁定即清零          │
│                                   │                                       │
│        本机 socket(仅本用户可读写) ├── 浏览器扩展(经 native host / Safari) │
│                                   ├── 终端 `rootkey` / AI 用的 MCP          │
│                                   └── SSH agent                            │
│                                                                          │
│  系统钥匙串 / Keystore:生物识别解锁用的包装密钥(须本人生物识别才能取)      │
│  手机系统自动填充扩展:读 App 解锁时留下的加密快照                           │
└──────────────────────────────────────────────────────────────────────────┘
         │ 只有密文                           │ 只有授权 / 中继 / 诊断数据
         ▼                                   ▼
┌──────────────── 不信任 ────────────────┐  ┌──────── 我们的服务器 ────────┐
│ 同步存储:iCloud / Dropbox / WebDAV /   │  │ 激活与授权、远程确认中继、   │
│ 本地文件夹 / 局域网直连的另一台设备      │  │ App 配置与公告、崩溃上报、   │
│ 假设可读、可写、可删、可回放旧文件       │  │ 反馈。**不接触任何保险库数据** │
└────────────────────────────────────────┘  └──────────────────────────────┘
```

Rust 核心里只有加密部分(`crypto_core`)在本仓公开;保险库、同步、本机接口等属于产品闭源层,都只调用 `crypto_core`,
不各自实现密码学。下文对闭源部分的描述以产品代码为准。

- **信任**:Rust 进程内存、落盘前的明文、本人设备上的操作系统。
- **有限信任**:系统钥匙串 / Secure Enclave / Android Keystore —— 信任系统隔离,不对越狱 / Root 设备做承诺。
- **不信任**:同步存储与传输网络、我们自己的服务器(按「服务器被攻破」设计:它手里没有可解密的东西)。

## 2. 密钥体系摘要

```
主密码 ──Argon2id(默认 m=128 MiB, t=3, p=4)──> MUK ──包装──> 账户根密钥 ARK
ARK ──> 各保险库 KEK ──> VMK ──> IKEK ──> 每条目独立的 ItemKey
```

- **没有 Secret Key / 设备密钥**:主密码是唯一的知识因子(ADR-001)。拿到加密数据的人只能离线爆破主密码,
  Argon2id 参数决定代价。低于 OWASP 基线(19 MiB / t=2 / p=1)的参数一律拒绝解锁。
- **恢复密钥**(应急套件上的 `RK-` 串,125 位随机熵)**单独就能解开账户并重设主密码**。它和主密码同级,
  必须当作主密码一样保管;丢了它不影响安全,泄露了等于主密码泄露。
- **生物识别解锁**:钥匙串里存一把 32 字节包装密钥,访问控制为「当前录入的生物特征 + 每次验证」,
  重新录入指纹 / 面容后自动失效。它解开本地的生物识别包装文件,得到 ARK。
- 条目内容用 XChaCha20-Poly1305,包装密钥用 AES-256-GCM-SIV;随机数全部取自系统 CSPRNG,调用方不能指定。
- 每个保险库一对 Ed25519 签名密钥,本地的索引、条目、历史都有签名,打开时校验。

## 3. 攻击者能力分级

| 等级 | 能力 | 结论 |
|---|---|---|
| **A1 网络被动监听** | 抓同步 / 授权流量 | 防:同步内容是密文;服务器通信走 TLS。WebDAV 若填 http:// 地址,登录凭据会明文过网(内容仍是密文);请用 https |
| **A2 网络主动篡改** | 中间人改包 | 防:条目逐个 AEAD + 索引里的内容哈希;改动即解密 / 校验失败 |
| **A3 同步存储被攻破** | 拿到网盘里的全部文件 | 防内容泄露:需爆破主密码。见第 4.2 节它**仍能做到**的事(删除、冻结、看元数据) |
| **A4 设备被拿走(已锁)** | 锁定状态的电脑 / 手机 | 防:需主密码或本人生物识别。**没有**失败次数上限,主密码错误不会触发清空 |
| **A5 设备被拿走(解锁中)** | 解锁状态的设备 | **部分**:默认 5 分钟无操作自动锁;**电脑睡眠 / 锁屏时目前不会跟着锁**(局限 L6) |
| **A6 进程内存读取** | root / 调试器读 RootKey 进程 | **部分**:解锁期间密钥必然在内存;锁定后清零。未使用 mlock,内存可能被换出到磁盘 |
| **A7 同用户的其他程序** | 电脑上以你的身份运行的恶意程序 | **不防**:本机 socket 对同一用户的进程开放(见 4.4)。这类程序同样能记录键盘、截屏,属于操作系统层面的失守 |
| **A8 恶意网页** | 你在浏览器里打开的任意网站 | 防:扩展只按页面真实来源取用对应站点的凭据;通行密钥绑定真实站点(0.23.1 修复,见第 9 节) |
| **A9 扩展供应链** | 攻击者控制了扩展更新 | **部分**:扩展本身不存保险库,但被替换的扩展可以向桌面 App 请求任意站点的凭据 |
| **A10 越狱 / Root 设备** | 系统隔离已被打破 | 不承诺:钥匙串 / Keystore 中的包装密钥可能被读出 |
| **A11 离线爆破** | 拿到加密文件 + 密钥包 | 只靠主密码强度 + Argon2id。**强主密码是唯一防线** |
| **A12 本机 AI(正常工作)** | 经 MCP / 终端读写你开放的条目 | 防:没开放的条目对 AI 不存在;「可用不可见」的密钥不进对话(只注入 / 代填);由 App 侧强制,AI 不能给自己开权限 |
| **A13 本机 AI(恶意 / 被注入)** | 有 shell,存心套取 | **不防**:能执行任意命令的 AI 等同 A7。它可以把注入的值编码后打印,也可以冒充人(局限 L3) |
| **A14 我们的服务器被攻破** | 拿到授权库、中继、日志 | 防保险库:服务器上没有保险库数据,也没有主密码。能拿到的是邮箱、设备指纹哈希、授权记录,0.23.1 及以前还能伪造远程确认中继的请求与答复(局限 L9,下一版已修) |

## 4. 各组件

### 4.1 本机存储

保险库目录:`vault.json`(**明文**:格式版本、保险库 id、显示名、创建时间、签名公钥、被包装的签名私钥)、
`manifest.enc`(加密索引:标题、副标题、标签、收藏、AI 权限、提醒到期日、网址主机名)、`items/` / `history/` /
`trash/` / `attachments/`(每条一个文件,内容加密)。文件个数可以看出条目数量。

### 4.2 同步存储

支持 iCloud、Dropbox(官方授权,仅限应用文件夹)、WebDAV、本地文件夹、局域网直连。同步凭据(WebDAV 密码、
Dropbox 令牌)用本保险库的密钥加密后存本地,不进钥匙串,也不同步出去。

远端每个保险库一个目录:

| 文件 | 内容 | 谁能读 |
|---|---|---|
| `keyset.bundle` | 明文 JSON:账户 id、KDF 参数与盐、本账户所有保险库的 id、**被包装过的各级密钥**、推送设备 id、版本号 | 任何能读网盘的人(据此可离线爆破主密码) |
| `sync.manifest.enc` | 加密的同步索引(各条目版本与内容哈希) | 只有持主密码的设备 |
| `items/*.blob` | 每条一个,外层 JSON 含条目 id、版本、各时间戳(明文),内层内容加密 | 内容只有持主密码的设备 |

**完整性与防回滚**:同步索引是 AEAD 加密的,并记录每个条目文件的哈希,单独回放某个旧条目会被拒;索引版本低于本机见过的会被拒,
索引消失会报错而不是当成空库。`keyset.bundle` 用单调版本号防回滚,本机记下的「见过的最高版本」本身是加密的。

恶意的同步存储**仍然能**:删除文件 / 拒绝服务;停止更新(没有新鲜度证明,你会一直看到旧数据);
拿 `keyset.bundle` 离线爆破;通过文件名、时间戳、大小做元数据分析;在 0.23.1 及以前,改大 `keyset.bundle` 的明文版本号可绕过它的回滚检查(局限 L8,下一版已修)。
新设备首次接入时没有本机记录可比,只能信任第一次看到的内容。

冲突按「后修改的生效」处理,另一版完整进入条目历史,可以按字段恢复。

### 4.3 局域网直连

桌面端在解锁期间起一个只在局域网可达的 HTTPS 服务(自签证书),锁定即停。手机配对方式两种:

- **扫码**:二维码里带证书本身,手机直接钉住它 —— 防中间人。
- **自动发现 + 6 位配对码**:证书指纹来自局域网广播,可能被同一网络的人冒充。
  下一版起配对改用 SPAKE2:配对码参与密钥协商而不在线路上出现,双方证明里绑定各自 TLS 上
  实际看到的证书指纹 —— 冒充者换了证书就对不上,每次尝试只等于在线猜一个码(5 次关窗)。
  0.23.1 及以前用的是明文比对配对码,自动发现路径可被冒充(局限 L4)。

配对码 5 分钟有效、错 5 次作废。下一版起已配对设备在桌面端「已连接的设备」里列出、可随时移除,
盘上只存令牌的哈希。
传输的只有同步文件,主密码和明文密钥从不经过网络。

### 4.4 本机接口(浏览器扩展、终端、AI)

所有本机客户端通过一个 Unix socket 与 App 通信(macOS 在 App Group 容器里,目录 0700、socket 0600,
拒绝符号链接)。另有一个 `cli.token`(32 字节随机,0600,每次 App 启动重新生成),终端 / 项目 / AI 代填类请求要带它。

**信任边界是「本机同一用户」**:能以你的身份运行程序的人,读得到 socket 和令牌,这一层不再区分。
0.23.1 及以前,调用方代码签名校验只记日志、不拒绝(局限 L1)。下一版起(macOS):浏览器取用类请求只接受
我们团队签名的程序;native host 启动时核对父进程是浏览器 —— 浏览器后台自更新后也能认出(改验磁盘上的新版本)。

**浏览器扩展**:扩展本身不存任何保险库数据,也不做加解密,只按「当前页面的真实来源」向桌面 App 请求该站点的凭据。
桌面 App 再做一遍:来源必须 https;条目网址与来源主机相同或同属一个注册域(按公共后缀表算);第三方 iframe 里的请求拒绝。
填充前检查目标输入框可见、未被遮挡,只响应真实的用户手势。
**通行密钥**(0.23.1 起):站点 id 必须是页面真实来源的主机或其上级域,且不能是公共后缀;签名前核对客户端数据里的来源与类型。
页面脚本只能经中转调用通行密钥这两个动作。UV(用户验证)标志如实为 false。

**终端与 AI**:调用方是 AI(MCP,或被判定为 AI 的终端)时,只能看到你开放了 AI 权限的条目;
「可用不可见」档的密钥以打码返回,只能经 `rootkey run` 注入子进程或由 App 代填登录;AI 写入不需要桌面确认,但只限它看得到的条目;
每次 AI 读写都加密记入访问记录。人在终端读取未开放给 AI 的明文时,桌面弹确认(同一终端 10 分钟内免确认)。

终端区分「人」和「AI」靠调用方自报(环境变量 / 是否交互终端),所以 AI 冒充人是可能的(局限 L3)。

### 4.5 手机

**iOS**:主 App 解锁时把可填充的条目(含密码与 TOTP 种子)加密成快照放进 App Group,会话密钥放共享钥匙串
(本机、首次解锁后可读);开了面容 ID 时另存一份需要生物识别的副本。锁定时删会话密钥,冷启动时清残留。
交给系统用于提示的只有网址 / 标题、用户名、条目 id(通行密钥是站点 id 与用户名)。系统通行密钥由 iOS 核对站点。
进入后台时盖上启动画面,多任务界面看不到内容。

**Android**:快照放在不参与备份的私有目录,数据密钥只在内存;生物识别副本用 Keystore 密钥包装,
要求强生物识别、每次验证、重新录入即失效。通行密钥校验调用方是系统认可的浏览器并核对站点归属。
Android 13+ 关闭最近任务截图;复制时标记为敏感内容。

手机端共同局限:自动锁不是「立即」时,App 切走后要等回到前台才判断超时(局限 L5);
系统自动填充在主 App 未锁时可以不验证直接填(与主流密码管理器一致,但意味着解锁窗口内手机被拿走即可填充)。

### 4.6 我们的服务器

| 用途 | App 发送 | 服务器保存 |
|---|---|---|
| 激活 / 每日复验 / 解绑 | 激活码、可选邮箱、设备指纹(机器 id 的 SHA-256)、系统、App 版本 | 邮箱、订单与授权、设备指纹哈希、系统、版本、首末次出现时间。**不存设备名,不存 IP** |
| 远程确认中继 | 设备公钥、推送令牌;请求 / 答复是封给对方设备公钥的密文 | 设备公钥与推送令牌;密文 180 秒后丢弃 |
| App 配置与公告 | 平台 | — |
| 崩溃上报(先询问,同意后才发;0.23.1 及以前默认开) | 错误类型、打码后的错误信息、前 40 行堆栈、平台、系统与 App 版本 | 同左 |
| 反馈 | 你填写的邮箱、内容、截图、设备信息 | 同左 |

离线授权令牌由服务器 Ed25519 签名、App 内嵌公钥离线验证;复验失败或离线时继续用缓存令牌。
服务器从不接收主密码、保险库数据或条目网址。

### 4.7 其他联网

- **网站图标**:只向条目所属网站本身请求 `/favicon.ico` / `/apple-touch-icon.png`,与你打开该网站时浏览器的行为相同。
  0.23.1 之前取不到时会改问 Google 的图标服务,等于把域名告诉 Google,已移除。
- **泄露检查**(默认关):只发送密码 SHA-1 的前 5 位到 Have I Been Pwned,带填充防长度分析。
- **「去改密码」**:仅在你点按钮时,向该网站请求一次 `/.well-known/change-password`。
- **自动更新**:macOS 读 appcast 并校验 EdDSA 更新签名;Android 下载后校验 SHA-256,由系统让你确认安装。
- 没有第三方统计 / 广告 / 崩溃 SDK。

## 5. 元数据泄露

| 谁能看到 | 能看到什么 | 看不到什么 |
|---|---|---|
| 同步存储 | 条目数量、每条大小、条目 id、修改次数、各时间戳、同步频率、账户下有几个保险库、KDF 参数 | 标题、网址、用户名、密码、标签、备注、附件内容 |
| 局域网 | 桌面端的设备名(主机名)、证书指纹、正在提供同步 | 同上 |
| 我们的服务器 | 你的邮箱、几台设备、各设备系统与版本、何时在用 | 任何保险库内容与条目网址 |
| 网站 | 你的设备在取它的图标(说明你可能存了它的账号) | — |
| 手机系统 | 可填充条目的网址 / 标题与用户名(用于填充提示) | 密码 |

## 6. 明确不在保护范围

1. 键盘记录、截屏、恶意程序以你的身份运行(A7 / A13)—— 操作系统层面的失守
2. 在不可信设备(公用电脑、远程桌面)上输入主密码
3. 你主动截屏、录屏、复制后粘贴到别处
4. 忘记主密码且没有恢复密钥:没有任何找回途径
5. 同步存储删除数据:我们能发现并提示,但不能恢复;请保留至少一台设备上的副本
6. 依赖库 0day:跟进披露并升级,但目前没有自动化依赖漏洞扫描(局限 L10)
7. 抗量子:当前算法不抵御大规模量子计算机
8. 恶意 AI 套取「可用不可见」条目:这一档防的是正常工作的 AI 把值带进对话;对不信任的 AI,条目保持「无权限」,
   并不要让 AI 客户端免确认执行任意命令

## 7. 不变量

- **N1** Argon2id 参数低于 OWASP 2024 基线的保险库必须解锁失败
- **N2** 同一密钥下不出现重复随机数(随机 nonce,调用方不能指定)
- **N3** 主密码按 NFKD 归一化,不同输入法打出的同一密码派生同一密钥
- **N4** 落盘前所有条目内容都经 AEAD 加密
- **N5** FFI 返回给界面层的对象不含原始密钥字节
- **N6** 主密码错误与密文被篡改在错误上不可区分
- **N7** 解锁失败不改变后续解锁的成功率(没有失败锁定,也没有失败清空)
- **N8** 浏览器扩展取用凭据以页面真实来源为准,来源必须 https,条目网址须与来源同站
- **N9** 通行密钥的 UV 标志如实置位;站点 id 必须是真实来源的主机或其上级域(0.23.1 起)
- **N10** AI 调用方只能碰开放了 AI 权限的条目;「可用不可见」的密钥不以明文返回给 AI(注入与代填除外),由 App 侧强制

N1–N7 由加密核心与保险库测试覆盖;N8–N9 由本机接口单测与浏览器端到端测试覆盖;N10 由本机接口单测与 MCP 契约测试覆盖。

## 10. 相对 v1.x 的更正

- 删除「生物识别 N 次失败清空缓存」:代码里没有这个机制(见 N7)
